# 《地心奇境》重构设计 · 横版探索世界 + 仪器探测

> 版本 v1 · 目标:科学性 / 创新性 / 实用(留住用户) / 可实现(时间与难度可控、保留拓展性)

---

## 0. 一句话愿景

把现在"各自为政、彼此雷同"的模块(笔记本按层、实验室按层、地壳游戏独立)重构成**一个统一的横版探索世界**:玩家扮演一名地心探险者,**左右走动探索**每一层地球,**走近正在发生的现象**就能了解"发生了什么、为什么",并通过**逐层获得的探测仪器**回访前面的世界、解锁此前"看不见"的内容。

---

## 1. 为什么这样重构

### 1.1 现状病根
- **无主线脊梁**:三个模块都在"按地壳/地幔/地核分层",同一结构被实现多遍。
- **交互雷同又割裂**:每个模块都是一个孤立小交互,玩完即散,互不牵引。
- **知识与玩法分离**:笔记本是"读",游戏是"玩",没有"在玩中自然学到"。

### 1.2 新范式如何治病
| 目标 | 落地方式 |
|---|---|
| 科学性 | 现象点对应真实地球物理;"仪器=感知手段"本身就是真实的科学观测方式 |
| 创新性 | 横版探索 + 现象发现 + 仪器回访(类"银河恶魔城"轻量版),科普 App 中罕见 |
| 实用/留人 | 探索欲 + 收集图鉴 + 回访解锁 + 通关沙盒,形成长期粘性 |
| 可实现 | 复用已有 SpriteKit 与数据层;数据驱动;MVP 单层起步,分期扩展 |

---

## 2. 核心玩法:横版探索世界

### 2.1 基本循环
```
进入某层世界 → 左右走动探索 → 靠近"现象点(POI)"
  → 现象被激活(动效播放)→ 发现卡:发生了什么 + 为什么
  → 收获(图鉴/知识点/勋章)→ 继续探索或下潜到下一层
```

### 2.2 三层立体结构(厚度来源)
```
① 主线脊梁：地表→地心的下潜顺序（教学节奏 + 剧情牵引）
② 每层小世界：可横向探索，含 3~4 个不同类型的现象点
③ 跨层系统：图鉴收集 / 仪器回访 / 探究任务 / 通关沙盒（长期粘性）
```

### 2.3 现象点(POI)的四类交互(避免单调)
- **观察型**:走近即播放真实现象动效 + 发现卡(如对流柱翻涌)。
- **探究型**:小型"预测→观察→结论"(POE),先猜再验证。
- **采集型**:采集岩石/矿物/样本进图鉴。
- **操作型**:该层专属小游戏(造地貌 / 引爆火山 / 稳住磁场)。

---

## 3. 世界结构与主线

四层世界,自上而下下潜。每层是一个可横向滚动的 SpriteKit 场景,含若干 POI:

| 层世界 | 氛围 | 现象点示例(混合四类交互) |
|---|---|---|
| **地壳** | 明亮、岩层、洞穴 | 造地貌(操作,复用现有地壳游戏)· 三大类岩石采集 · 化石年代小谜题 |
| **地幔** | 炽热、暗红、流动 | 对流柱(观察)· 岩浆房调成分触发火山(操作)· 钻石结晶采集 |
| **外核** | 液态金属、幽蓝 | 地磁发电机稳定(操作)· 磁力线观察 · "磁暴防护"挑战 |
| **内核** | 高压、致密、金属光 | 地震波扫描揭示结构(操作)· 高压结晶采集 · 内核差速自转(观察) |

**层间过渡**:下潜过场复用现有实验室"下落"场景与 `EarthPhysicsEngine`,途中显示真实温压变化(把旧实验室资产收编,不浪费)。

## 4. 仪器与回访机制(解决"知识点如何划分")

### 4.1 划分法则(核心,极简且科学)
> **每层给一件"招牌仪器",一件仪器 = 一种"感知能力"。现象点按"需要哪种仪器才能被看见"来归类。**

现实中科学家正是靠不同仪器感知不同现象——这个法则本身就是真科学。它把"知识点归属"变成一个**单一标签**,无需手工维护复杂依赖图。

### 4.2 仪器 → 回访解锁表
| 通关某层获得 | 该仪器能"看见"的知识点 | 典型回访解锁 |
|---|---|---|
| 地壳:**岩石采样钻** | 肉眼可见的岩石/化石/地貌 | (本层使用) |
| 地幔:**热成像仪** | 地下的热/未出露岩浆/地热 | 回地壳:温泉、地下热点 |
| 外核:**磁力仪** | 磁性矿物、磁力线 | 回地壳/地幔:磁铁矿、指南针原理 |
| 内核:**地震波扫描仪** | 隐藏断层、深部结构 | 回任意层:"透视"岩层与边界 |

### 4.3 数据驱动
新增知识点时只需给它标一个 `requiresInstrument` 标签;是否可见 = 玩家是否已拥有该仪器。**加内容 = 加数据**,不改逻辑。

### 4.4 分期交付(降低难度)
MVP 阶段回访可"设计先行、后交付":先埋 **1 件仪器(热成像仪)** 作样板证明机制,后续再扩其余仪器与回访点。

## 5. 数据模型(数据驱动,接现有内容层)

新增 JSON(放 `Core/Content/`,由 `ContentStore` 加载),示意:

**Worlds.json**(层世界)
```
{ id, index, title, mood, backgroundAsset, widthScreens, rewardInstrumentId }
```

**POIs.json**(现象点)
```
{
  id, worldId, x,               // 世界内水平位置
  title, phenomenon,            // "发生了什么"
  explanation,                  // "为什么"（科学解释）
  interactionType,              // observe | inquiry | collect | operate
  interactionRef,               // 操作型指向具体小游戏；探究型指向 POE 谜题
  requiresInstrument,           // 需要的仪器 id（无则默认可见）
  collectibleId,                // 采集掉落（可空）
  unlockOnDiscover: [ ... ]     // 发现后解锁的知识点/勋章（接 UnlockRuleEngine）
}
```

**Instruments.json** / **Collectibles.json**
```
Instrument:   { id, name, icon, perceptionTag, funFact }
Collectible:  { id, name, category, image, worldId, funFact }
```

对应 Swift 模型 `WorldLayer / POI / Instrument / Collectible` 加进 `ContentModels.swift`。

## 6. 跨层系统(长期粘性)

1. **图鉴收集**:岩石/矿物/现象散落各层,凑齐才完整 → 回访动机。
2. **仪器回访**(第 4 节):后期知识反照前期,教育意义 + 耐玩性。
3. **探究任务线**:动态任务在多层间派遣("对比地幔与外核密度差")。
4. **"我的地球"沙盒**:通关后解锁,把所有机制放进可自由玩的地球剖面(收编旧实验室的自由探索属性)。

---

## 7. 数据层评估:**复用,不重开**(回应"是否要重来")

**结论:不需要重新开始项目。** 我们刚完成的数据层正是这套玩法的理想地基,只做**增量扩展**:

| 现有组件 | 新玩法下的角色 | 需要的改动 |
|---|---|---|
| `ContentStore` | 加载世界/POI/仪器/图鉴 JSON | ✅ 加 JSON + 模型(纯增量) |
| `ProgressStore`(CoreData) | 存"已发现 POI / 已获仪器 / 已采集图鉴 / 各层进度" | ✅ `UnlockKind` 增 `poi/instrument/collectible` 三个枚举值;`LabLevelProgress` 泛化为 `WorldProgress`(或新增) |
| `UnlockRuleEngine` | 发现 POI → 解锁知识/图鉴;通关层 → 授予仪器 | ✅ 事件模型天然适用,`UnlockRules.json` 加 `poi.*/world.*` 规则 |
| `GameProgressManager` / `LegacyMigrator` | 门面与迁移 | ✅ 原样复用 |

> 因此建议**保留现有仓库继续演进**,不要重开——重开会浪费已验证、已构建通过的地基,且失去迁移器保护老用户数据的能力。

## 8. UI / 美术策略 + AIGC 管线(你最担心的一点)

美术是本方案唯一"重"的地方,但可以用 **AIGC + 数据化 + 解耦** 把风险压到最低。

### 8.1 先定"风格样板(Style Bible)"
- 统一风格:**扁平卡通 + 地球剖面**质感,暖色系(参照现有 `big.jpg`、现有 Assets 风格)。
- 固定要素:统一线宽、统一调色板(每层一个主色:地壳暖黄 / 地幔橙红 / 外核幽蓝 / 内核金属)、统一光照方向。
- 先用 AIGC 生成 3~5 张**风格参考图**并锁定,作为后续所有素材的"锚"。

### 8.2 素材清单(按优先级)
1. 每层**视差背景/岩层**(横向可拼接)。
2. 主角/探测器 sprite(idle + walk 少帧)。
3. **现象点插画**(火山、对流柱、结晶、磁力线…)。
4. UI:发现卡、按钮、仪器图标、图鉴缩略图。
5. 特效(粒子:岩浆、磁光、结晶闪光)。

### 8.3 AIGC 工作流(保证一致性)
1. **风格锁定**:用参考图 + 统一 prompt 模板(固定风格描述 + 调色板词);同族 seed / 参考图 img2img,保证多张素材风格一致。
2. **批量生成**:按清单逐类生成;每类先出 2~3 版挑选。
3. **后处理**:抠图去背景(remove.bg / SD)、统一尺寸、切图打包进 `.spriteatlas`(项目已用此格式)。
4. **动画省力**:角色走路用**少帧 + SKAction 挤压/拉伸/摆动**,避免大量逐帧;现象动效优先用 SpriteKit 粒子 + 变换,少依赖美术帧。
5. **资源数据化**:所有资源名写进 JSON,便于**边做边替换、后期升级美术**。
6. **解耦兜底**:先用色块/占位图把**玩法逻辑**跑通,美术后补——**美术不阻塞开发**。

工具建议:图像生成(Midjourney / Stable Diffusion / DALL·E,或国内即梦、文心一格、通义万相);抠图切图(remove.bg、TexturePacker)。

## 9. 技术架构(复用 SpriteKit)

```
World/
├─ Scenes/  WorldScene.swift          (横版场景:相机跟随、视差、POI 布置)
├─ Nodes/   PlayerNode / POINode / ParallaxLayer
├─ Controllers/ WorldViewController    (承载 SKView + HUD:仪器栏/图鉴入口)
├─ ViewModel/  WorldViewModel          (读 POI 数据、发现判定、解锁触发)
└─ Discovery/  DiscoveryCardView / CollectionViewController(图鉴)
```
- **控制**:左右虚拟按钮或屏幕拖拽移动;靠近 POI 触发"发现"提示。
- **相机**:`SKCameraNode` 水平跟随,视差背景。
- **迁移**:地壳造地貌游戏 → 包成 `operate` 型 POI;下潜场景 → 层间过场;笔记本知识 → 发现卡内容(数据来自 `NotebookKnowledge.json`)。

## 10. MVP 边界与分期路线图

**MVP(小、快、效果不差)——只做地壳层**
- 一个可左右走的地壳世界 + 3~4 个 POI(含复用的造地貌游戏)。
- 走近 → 发现卡(发生了什么 + 为什么)。
- 埋 1 件仪器(热成像仪)作回访样板。
- 全部数据化;美术先占位、AIGC 逐步替换。

**分期**
- 阶段 1:世界壳 + 地壳 POI + 发现卡 + 数据模型扩展(复用数据层)。
- 阶段 2:图鉴系统 + 采集型 POI + 1 件仪器回访跑通。
- 阶段 3:地幔世界 + 火山/对流机制。
- 阶段 4:外核(地磁)、内核(地震波)世界。
- 阶段 5:探究任务线 + "我的地球"沙盒 + 美术终版。

## 11. 现有模块迁移映射

| 现有模块 | 去向 |
|---|---|

| 勋章 | 保留,接入发现/收集/通关事件 |
| AI 伙伴 | 保留,升级为"世界向导",在 POI 旁给情境化讲解(与已规划的 AI 情境化打通) |

## 12. 风险与取舍

| 风险 | 应对 |
|---|---|
| 美术工作量与一致性 | AIGC 风格锁定 + 数据化替换 + 占位图解耦,美术不阻塞逻辑 |
| 横版控制手感 | MVP 先验证走动 + 靠近触发,再打磨 |
| 回访依赖复杂度 | "一层一仪器"单标签法则,分期交付 |
| 时间有限 | 单层 MVP 起步,复用地壳游戏/下潜/数据层,增量扩展 |
